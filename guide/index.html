Ayuda y diagnóstico

Cómo usar esta guía

Esta página se debe usar como punto de entrada. Para una primera aproximación al proyecto, se recomienda seguir la secuencia propuesta. Ante una tarea concreta, se puede acudir al mapa de capacidades. Para diagnosticar un error, se debe consultar directamente Ayuda. La idea no es leer todo de memoria: primero se debe ubicar la responsabilidad y después entrar al archivo o contrato correspondiente.

  1. O

    Orientación

    Entender vocabulario, superficies y responsabilidades sin entrar todavía al código.

    Vocabulario Modelo del proyecto

  2. C

    Construcción

    Identificar qué archivo toca una tarea concreta: página, fragment, JSON, outbound, sesión, assets o UI progresiva.

    Gateway Surface Bridge

  3. P

    Profundidad

    Entrar a contratos, lifecycle, errores, assets y composición completa.

    Mapa de capacidades Diagramas

  4. A

    Aplicación

    Ejecutar cambios concretos, validar conexiones y diagnosticar fallos esperados.

    Prácticas Referencia Diagnóstico

Cada página abre con un mapa corto y luego entra en detalle. Para validar comportamiento, se debe revisar el código, la configuración y la estructura real del proyecto.

Mapa de capacidades

Este mapa sirve para comenzar por la necesidad concreta, sin recorrer toda la arquitectura antes de actuar. Primero se debe reconocer qué resultado se busca: entregar HTML, intercambiar datos o activar comportamiento en el navegador. Después se sigue la línea correspondiente hasta las páginas, contratos y prácticas que explican cómo construirlo.

SSR / HTML Datos / contratos Runtime / experiencia

SSR / HTML

Páginas y fragmentos que nacen en Gateway y se activan en Surface.

  1. Página SSR activable

    Ruta y vista SSR en Gateway; integración registrada y binding de página en Surface.

    Gateway
    Route · Controller · renderControlView(...) / renderAccessView(...)

    data-surface-page · integration.ts · page.ts · UiBinding · registry.ts

L2

Datos / contratos

JSON, salidas externas y errores que deben conservar contratos visibles.

  1. Endpoint JSON

    Gateway adapta el use case al envelope; Surface declara contratos y consume datos tipados.

    Gateway
    Controller · Use case · respondJson(...) · UseCaseResult
    Surface
    contracts.ts · api.ts · actions.ts · serverClient.data(...) / serverClient.json(...)
    Escenario JSON

  2. Integración externa

    Gateway modela connectors y composición; Surface consume solo el endpoint expuesto.

    Gateway
    *ConnectorInterface · Connector · Outbound client · ConnectorResult · Service opcional
    Surface
    Contrato HTTP Gateway visible para Surface
    Escenario outbound

  3. Degradación o error visible

    Gateway distingue carriles y parcialidad; Surface presenta advertencias y errores clasificados.

    Gateway
    takeOrAbort(...) · ConnectorFlowInterface · required(...) / optional(...) · errorKind
    Surface
    PartialReporter · SessionError · UserActionError · FatalError
    Escenario errores
L3

Runtime / experiencia

Sesión, assets y capacidades visuales que sostienen la experiencia progresiva.

  1. Sesión por pestaña

    Gateway resuelve la pestaña activa; Surface hidrata y sincroniza la vigencia recibida.

    Gateway
    TabSessionRequestResolver · X-TAB-SESSION · X-TAB-SESSION-NAV · X-REMAINING
    Surface
    sessionStorage · input SSR _tab · X-TAB-SESSION · X-REMAINING
    Escenario sesión

  2. Assets Vite y base HTTP

    Gateway publica assets y base HTTP; Surface genera manifest y construye solicitudes.

    Gateway
    vite_styles() · vite_script() · manifest · modulepreload · window.__BASE_URL__
    Surface
    vite.config.ts · baseUrl(...) · window.__BASE_URL__
    Escenario assets

  3. UI enriquecida bajo demanda

    Gateway entrega HTML o JSON; Surface activa adapters visuales y libera recursos al desmontar.

    Gateway
    HTML o JSON sin conocimiento de adapters de UI
    Surface
    Toolkit · Adapters · UiBinding · contentMount · Cleanup · Vendors lazy
    Escenario UI
