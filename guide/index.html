Cómo leer esta guía

Esta guía está escrita en dos capas: primero una síntesis para ubicar el tema dentro del recorrido; después el detalle amplio para construir, diagnosticar y mantener una feature completa. Cuando un término no resulte claro al inicio, la referencia recomendada es el vocabulario y luego la ruta de lectura.

Capa Qué resuelve Lectura recomendada
Orientación Entender vocabulario, superficies y responsabilidades sin entrar todavía al código. Vocabulario mínimo y modelo mental.
Construcción Identificar qué archivo corresponde a página, fragment, JSON, outbound, sesión, assets o UI progresiva. Gateway, Surface y Bridge.
Profundidad Aprender contratos, lifecycle, errores, parcialidad, observabilidad, adapters, Vite y composición completa. Matrices de capacidades, secciones internas y lista de diagramas.
Aplicación Convertir lo aprendido en cambios concretos y validar que todo siga conectado. Guías paso a paso, referencia y diagnóstico.

Resumen no significa recorte: cada página empieza con el mapa corto y después desarrolla el detalle. La fuente de verdad técnica sigue siendo el código, la configuración y el filesystem real.

Para una lectura sin una tarea puntual, el recorrido recomendado inicia en Empezar y continúa con Bases, donde se explica cómo se conectan las páginas siguientes. Cuando necesites crear componentes o contratos, salta a Herramientas.

Matriz de capacidades

Esta tabla funciona como entrada por tarea. Los ejemplos usan nombres neutrales y placeholders: deben reemplazarse por la intención real del proyecto sin alterar los contratos entre Core, Extension y Surface.

Quiero crear Gateway Surface Mapa útil
Página SSR activable Route, controller, renderControlView(...) o renderAccessView(...). data-surface-page, integración, UiBinding y registro. Escenario página
Fragment HTML remoto Route, controller, renderFragmentView(...) y partial de error controlado. serverClient.html(...), validación expect, contentMount y fragment runtime. Escenario fragment
Endpoint JSON Controller + use case + respondJson(...) con UseCaseResult. contracts.ts, api.ts, serverClient.data(...), errores UI y respuesta parcial. Escenario JSON
Integración externa Port, connector, service si agrega valor, ConnectorResult y outbound client. No llama servicios externos; consume Gateway. Escenario outbound
Degradación o error visible required(...), optional(...), error kind/origin y envelope. Partial reporter, SessionError, UserActionError o FatalError. Escenario errores
UI enriquecida opt-in Entrega HTML o JSON; no conoce adapters UI. Toolkit, adapters, feedback, cleanup y vendors lazy. Escenario UI
