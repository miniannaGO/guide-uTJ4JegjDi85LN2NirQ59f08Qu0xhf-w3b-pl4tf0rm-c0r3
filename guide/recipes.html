Guías paso a paso

Escenarios frecuentes para crear features completas sin alterar contratos gateway/surface.

Cómo usar estas guías

Cada receta es una ruta de construcción. Primero se presenta el resumen del escenario para identificar el contrato involucrado; después aparece el checklist completo. Los pasos de verificación son obligatorios porque ahí suelen aparecer los errores de bridge. El orden baja desde Gateway hacia Surface: ruta, controller, salida HTML/JSON, outbound cuando exista, integración UI, sesión, assets y diagnóstico. Cuando una receta muestre un comando composer robo --, léelo como apoyo para crear el esqueleto: la explicación del flujo y la responsabilidad de cada archivo siguen siendo la parte principal.

La forma correcta de usar una receta es leerla como una lista de decisiones, no como una secuencia ciega de copiado. Antes de crear un archivo, identifica qué problema resuelve; antes de usar un comando, confirma qué artefactos va a tocar; y antes de dar por terminado el cambio, valida el contrato visible: HTML montable, JSON con envelope, sesión vigente, assets publicados o error trazable.

Crear una página SSR con comportamiento UI

Antes de crear archivos, debe revisarse cómo se conectan Controllers, Runtime de pages y fragments y Contratos HTML.

  1. Define primero la ruta, el controller, la vista SSR y el id Surface que conectará el HTML con la integración. Como ayuda para crear ese esqueleto inicial puedes usar composer robo -- make:integration-page <feature> --id=<data-surface-page> --layout=control|access. Por ejemplo: composer robo -- make:integration-page feature --id=feature-id --layout=control. Robo crea route, controller, view SSR, integración Surface, page binding, registry y menú cuando aplique; la intención de la página sigue definiéndose en esta receta.
  2. Agregar o ubicar la ruta en `Extension/Presentation/Http/Routing`.
  3. Crear el método en controller y usar `renderControlView(...)` o `renderAccessView(...)`.
  4. Crear la vista `.page.php` en `resources/views`.
  5. Cuando necesite JS, debe declararse `data-surface-page="feature-id"`.
  6. Crear `workspace/integrations/feature/integration.ts`.
  7. Crear `page.ts` con `UiBinding` o `mount(...)`.
  8. Registra la integración en `workspace/integrations/registry.ts`.
  9. Ejecutar `npm run lite:build` para compilar assets en modo watch local. Ese script ejecuta vite build --watch; para validación completa usa npm run build.

Crear un fragment dinámico

Los fragments son un contrato compartido: amplía en Contratos HTML y Runtime de pages y fragments.

  1. Si el fragment ya pertenece a una integración Surface existente y solo falta el binding, define primero el HTML del fragment, el id declarativo y cómo se insertará desde Surface. Como ayuda para el esqueleto puedes usar composer robo -- make:fragment <feature> <fragment> --id=<data-surface-fragment>. Robo crea fragments/<fragment>.ts, registra el loader en integration.ts y alinea el sufijo del archivo con el id cuando hay duplicados.
  2. Declara ruta de fragment bajo el grupo correcto.
  3. El controller responde `renderFragmentView(...)`.
  4. La vista `.fragment.php` devuelve HTML real.
  5. Cuando necesite JS, debe usarse `data-surface-fragment="fragment-id"`.
  6. Registra el fragment en la integración propietaria.
  7. Desde surface inserta el HTML con `serverClient.html(...)`; si el fragment es montable, declara el `fragmentId` esperado con `expect`.

Cargar fragment desde page binding 
import { serverClient } from "@/platform/infrastructure/http";
import { UiBinding } from "@/platform/runtime/binding";
import {
  mountHtmlContent,
  unmountHtmlContent,
  type MountedContent,
} from "@/toolkit/dom/content";

export default class ItemsPageBinding extends UiBinding {
  private summaryContent?: MountedContent;

  protected mount(): void {
    const button = this.require<HTMLButtonElement>("[data-load-summary]");
    this.onClick(button, () => this.loadSummary());
  }

  protected async unmount(): Promise<void> {
    await unmountHtmlContent(this.summaryContent);
  }

  private async loadSummary(): Promise<void> {
    const html = await serverClient.html("/items/summary", {
      expect: { kind: "fragment", fragmentId: "item-summary" },
    });

    const target = this.require<HTMLElement>("#item-summary-container");
    await unmountHtmlContent(this.summaryContent);
    target.innerHTML = html;
    this.summaryContent = await mountHtmlContent(target, this.contentMount);
  }
}

Crear un endpoint JSON

Para entender qué debe devolver este endpoint, consulta JSON envelope y HTTP, sesión y errores UI.

  1. Declara ruta.
  2. Controller prepara input y llama use case.
  3. Use case retorna `UseCaseResult`.
  4. Controller responde con `respondJson(...)`.
  5. En Surface, declara las firmas visibles del endpoint Gateway en `workspace/integrations/<feature>/contracts.ts`.
  6. `api.ts` importa esas firmas y tipa `serverClient.data(...)` o `serverClient.json(...)`.
  7. `actions.ts` arma el request tipado desde valores recibidos de `page.ts` o del fragment. `page.ts` debe quedarse leyendo DOM y llamando acciones.
  8. Surface consume con `serverClient.json(...)` o `serverClient.data(...)`.
Scaffold para endpoints consumidos por Surface 
composer robo -- make:integration-api-data <feature> <nameFunction> <method> <path> --controller-name=<ControllerName>
composer robo -- make:integration-api-data items searchItems post /items/search --controller-name=Items

composer robo -- make:integration-api-json items inspectItems get /items/inspect --controller-name=Items
composer robo -- make:integration-api-html items fetchPanel get /items/panel --controller-name=Items
API de integración Los comandos amplían una integración Surface existente.
  • Precondición workspace/integrations/<feature> Debe existir antes de ejecutar el comando.
  • Surface api.ts / CustomResponse Crea el archivo si falta y agrega una función async lowerCamelCase.
  • Gateway Registra la ruta y crea o completa el controller.
  • HTML .fragment.php Solo el modo html crea un fragment SSR base.
Ruta, controller y use case 
$router->post('/items/search', [ItemController::class, 'search']);
public function search(): HttpResponseInterface
{
  $input = SearchItemsInput::fromRequest($this->request);

  return $this->respondJson($this->searchItems->execute($input));
}

final class SearchItemsInput
{
  public function __construct(public string $query)
  {
  }

  public static function fromRequest(HttpRequest $request): self
  {
    return new self((string) $request->getJson('query', ''));
  }
}

final class SearchItems extends AppUseCase
{
  public function execute(SearchItemsInput $input): UseCaseResult
  {
    return $this->run(fn() => ['items' => []]);
  }
}
Contratos y API Surface

    Object.assign(this, data);
  }

    Object.assign(this, data);
  }

export function searchItems(request: SearchItemsRequest) {

Consumir un servicio externo

Esta receta cruza hacia un backend proveedor o API HTTP externa, que sirve como dependencia outbound: amplía en API HTTP clients externos, Flujo externo completo y Herramientas.

  1. Revisar `app-gateway/services.json`.
  2. Agregar overrides `API_<SERVICIO>_*` si hace falta.
  3. Crear o generar DTO en `Contract/Outbound`.
  4. Crear o generar request con `#[Endpoint]` bajo `Infrastructure/Outbound/Client/<Servicio>/Request`.
  5. Implementa connector en `Infrastructure/Outbound/Connector`.
  6. Definir o reutilizar un port en `Application/Port`.
  7. Consumir desde use case simple o service robusto.

Agregar un provider o resolver DI

Antes de un registro manual, se debe revisar Bootstrap y DI y confirma si autowiring o ConnectorAliasRegistrar ya resuelven la clase.

  1. Ubica si la pieza pertenece a Core o Extension.
  2. Si es transversal de Core, corresponde revisar RootProvider.php.
  3. Si es concreta de la app, corresponde revisar AppProvider.php.
  4. Para ports/connectors, primero intenta la convención *ConnectorInterface → *Connector.
  5. Registra manualmente solo si hay alias, runtime concreto o adapter externo.
  6. Si producción usa cache de contenedor, el deploy debe regenerarla o limpiarla.

Agregar una integración UI

Cuando se requiera lifecycle, limpieza o adapters, la referencia principal es Bindings y lifecycle y Workspace integrations.

  1. Crear carpeta en `workspace/integrations/<feature>`.
  2. Definir `integration.ts` con `id`, `layout`, `page.load` y fragments.
  3. Crear `page.ts` con `UiBinding` cuando se requiera lifecycle.
  4. Crear `contracts.ts` cuando haya payloads o responses JSON de Gateway visibles para Surface.
  5. Centraliza llamadas en `api.ts` y usa tipos de `contracts.ts`.
  6. Centraliza intención UI en `actions.ts`: recibe valores de `page.ts`, arma requests tipados y coordina feedback.
  7. Centraliza adapters repetidos en `controls.ts`.
  8. Registra la integración en `registry.ts`.

Montar HTML remoto dentro de modal o toast

La mecánica completa está en Content mount y el contrato HTML en Contratos HTML.

  1. Gateway debe devolver un fragment HTML embebible con renderFragmentView(...).
  2. Cuando el fragment tenga comportamiento, debe agregarse data-surface-fragment.
  3. Registra ese fragment en la integración propietaria.
  4. En el binding, usa simpleModal.withContentMount(this.contentMount) o toastAdapter.withContentMount(...).
  5. Si necesitas showRemote, importa modal o toast desde @/platform/infrastructure/feedback y declara expect si el contenido trae fragment montable.
  6. No deben ejecutarse scripts embebidos ni montarse fragments manualmente.
Modal remoto con contentMount 
import { simpleModal } from "@/platform/infrastructure/feedback";
import { UiBinding } from "@/platform/runtime/binding";

export default class ItemsPageBinding extends UiBinding {
  private readonly modal = simpleModal.withContentMount(this.contentMount);

  protected mount(): void {
    const button = this.require<HTMLButtonElement>("[data-open-summary]");
    this.onClick(button, () => this.openSummary("123"));
  }

  private async openSummary(itemId: string): Promise<void> {
    await this.modal.showRemote("/items/summary", {
      method: "GET",
      params: { itemId },
      expect: { kind: "fragment", fragmentId: "item-summary" },
    });
  }
}

Validar CSRF y tab session

Amplía la frontera entre ambos lados en CSRF y tab session y Seguridad, CSRF y sesión.

  1. La vista SSR de acceso debe imprimir el campo _csrf.
  2. Surface debe ejecutar ensureTabSession() en layout access/control.
  3. Si hay formulario, ensureTabSession() debe completar _tab.
  4. El controller valida CSRF antes de ejecutar el use case.
  5. Las rutas autenticadas leen X-TAB-SESSION desde serverClient.
  6. X-REMAINING debe llegar en respuestas para sincronizar expiración.

    public function login(): HttpResponseInterface
{
  $result = $this->runUseCase(function () {
    $csrfToken = (string) $this->request->getPost('_csrf');

    if (!$this->csrf->validate($csrfToken))
      return UseCaseResult::failure('Token CSRF inválido', ErrorKind::FORBIDDEN);

    $tabId = TabId::sanitize($this->request->getPost('_tab')) ?? '';

    return $this->loginCase->execute(new LoginCommand(
      usuario: (string) $this->request->getPost('txtUsuario'),
      contrasenia: (string) $this->request->getPost('txtContrasenia'),
      code: '0000',
      tabId: $tabId,
    ));
  });

  if (!$result->success) return $this->loginPage($result);

  return $this->redirectTo('/dashboard');
}

Mostrar un mensaje flash

La API vive en Controllers y el storage por pestaña se explica en Seguridad, CSRF y sesión.

  1. Ejecuta la acción de aplicación desde el controller.
  2. Si la acción termina bien y vas a redirigir, llama flashMessage(...).
  3. En la vista destino, pasa pullFlashMessages() como data para renderizar los avisos.
  4. No leas $_SESSION desde la view ni desde Surface.
Controller con flash 
public function store(): HttpResponseInterface
{
  $input = new SaveItemInput(
    name: (string) $this->request->getPost('name', '')
  );

  $result = $this->saveItem->execute($input);

  if ($result->success) {
    $this->flashMessage('success', 'Elemento guardado correctamente');
    return $this->redirectTo('/items');
  }

  return $this->renderControlView('items/form.page', fn() => $result);
}

public function index(): HttpResponseInterface
{
  return $this->renderControlView(
    'items/index.page',
    fn() => ['flashMessages' => $this->pullFlashMessages()]
  );
}

Diagnosticar route cache

El ciclo está explicado en Ciclo HTTP interno. Cuando una ruta nueva no aparezca en producción, el diagnóstico debe iniciar aquí.

  1. Confirmar que la ruta exista en el archivo correcto de Extension/Presentation/Http/Routing.
