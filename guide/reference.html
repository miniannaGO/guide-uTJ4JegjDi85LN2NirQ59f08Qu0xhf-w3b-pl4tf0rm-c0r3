Cómo usar la referencia

Esta página es una mesa de consulta rápida. No intenta explicar de nuevo Gateway, Surface, Bridge, instalación o troubleshooting; para eso ya existen páginas especializadas. Esta página resulta útil cuando el concepto general ya se conoce, pero se necesita confirmar el nombre exacto de una ruta, header, script, helper, status o señal de diagnóstico.

La regla editorial de esta página es deliberada: dar el dato corto y enlazar el lugar donde se explota el tema. Si una fila requiere más de una lectura para entenderse, la respuesta no debería crecer aquí; debería llevarte al flujo completo que le corresponde.

Rutas de carpetas

Las rutas permiten reconocer quién es responsable de un cambio. No hace falta memorizar todo el árbol: basta con distinguir si el archivo pertenece a entrada HTTP, aplicación, integración externa, comportamiento Surface o configuración compartida.

Si una ruta apunta a una capa concreta, la lectura debe continuar en Gateway, Surface o Contextos y límites.

Ruta Rol
app-gateway/app/Core Mini-framework interno.
app-gateway/app/Extension Aplicación concreta.
app-gateway/app/Extension/Application/Session Reglas compartidas de sesión/tab session.
app-gateway/resources/views Layouts, pages, fragments y parciales SSR.
app-surface/platform Startup, runtime, HTTP, sesión y errores UI.
app-surface/workspace Integraciones UI y estilos de aplicación.
app-surface/toolkit Adapters y helpers técnicos que se importan solo cuando se necesitan.
Contratos generados La clase principal respeta PSR-4 y los auxiliares quedan internos.
  • Comando http:contract Genera contratos PHP para Gateway outbound.
  • Archivo PSR-4 Una request o response principal por archivo.
  • Auxiliares @internal No son API pública de la aplicación.

Contratos rápidos

Un contrato es una forma acordada de intercambiar información entre dos partes. Esta tabla resume qué entrega cada frontera y quién la consume; se usa para confirmar una forma conocida, no para aprenderla sin el contexto de su capítulo principal.

Los contratos de esta tabla se desarrollan en Contratos HTML, JSON envelope y Headers de sesión.

Contrato Significado
success=true sin errores Éxito completo.
success=true con errores Respuesta parcial o degradada.
success=false Fallo bloqueante.
ApiResponse Envelope estable de Gateway para resultados de use case: success, data, message, code, errors y errorMeta cuando el runtime permite debug.
ViewData<TData> Envelope interno disponible como $viewModel en pages, fragments y parciales PHP. Expone success, data, message, errors y environment. La forma concreta de data se documenta al inicio de la vista con PHPDoc. Para datos estables puede usarse un ReadModel *Output conocido por use case, controller y vista. La plantilla lo usa directamente como modelo de lectura, sin envolverlo en otro DTO solo por llegar a HTML. Ver datos en la vista.
FlashMessageType Clasifica feedback de presentación como SUCCESS, INFO, WARNING o ERROR. La vista traduce el caso a su clase, icono o tratamiento visual; el enum no es una clase CSS.
JsonResponse JSON crudo sin envelope. No debe usarse como respuesta normal para endpoints que Surface consume con serverClient.json(...) o serverClient.data(...).
RedirectResponse Resuelve rutas relativas contra la base de la aplicación y respeta URLs absolutas, query string o hash ya explícitos.
data-surface-page Root de page UI.
data-surface-fragment Root de fragment UI.
contracts.ts de una integración Firma TypeScript de payloads y data JSON que Surface ve desde una ruta Gateway.
data-surface-page-status / data-surface-fragment-status Estado de montaje que Surface escribe para diagnosticar loading, mounted o error.
errors[] en envelope JSON Lista de errores visibles. Si success=true, indica respuesta parcial.
errorMeta Metadata técnica solo cuando el runtime permite exponer detalles de debug.
X-TAB-SESSION Identificador de pestaña enviado por surface.
X-TAB-SESSION-NAV Cookie técnica corta para navegaciones HTML normales que no pueden enviar el header X-TAB-SESSION.
X-REMAINING Tiempo restante de sesión emitido por gateway.
_flash.{tabId} Mensajes temporales de Gateway para el siguiente HTML SSR.
Surface La convención del código nuevo es TypeScript.
  • Compatibilidad tsconfig.json / allowJs Tolera código heredado, pero no define la convención normal de Surface.
  • Convención app-surface Integraciones, runtime, toolkit y workspace se escriben en TypeScript.

Headers HTTP

Los headers transportan datos de control junto al contenido principal de un request o una response. Para elegir el correcto se deben responder tres preguntas: quién lo envía, quién lo lee y qué decisión permite tomar.

El detalle operativo vive en Headers de sesión y CSRF y tab session.

Header Dirección Uso
X-TAB-SESSION Surface → Gateway Identifica la pestaña activa para rutas autenticadas.
X-TAB-SESSION-NAV Navegador → Gateway Cookie técnica de navegación HTML. Solo ayuda a recuperar la tab activa en requests GET; no reemplaza autenticación ni autorización.
X-REMAINING Gateway → Surface Sincroniza el contador de expiración de sesión.
X-CORRELATION-ID Gateway → navegador/logs Permite rastrear una request entre UI, Gateway y upstreams.
Accept Navegador/Surface → Gateway Indica si se espera JSON, HTML completo o fragment HTML.
Content-Type Ambos lados Debe coincidir con JSON, form-data o HTML esperado.

Errores y status

El status HTTP describe el resultado del intercambio; el error de aplicación explica qué impidió completar la intención solicitada. Ambos deben ser coherentes, pero no significan lo mismo. La tabla ayuda a contrastar esas dos capas sin reducir todos los fallos a un número HTTP.

Para semántica completa, se debe consultar Errores y resultados y Contratos de error HTTP.

ErrorKind Status típico Lectura rápida
BAD_REQUEST 400 Request mal formado o imposible.
VALIDATION 422 Input inválido para la intención de aplicación.
AUTHENTICATION_REQUIRED 401 Falta sesión válida.
FORBIDDEN 403 Sesión existe, pero la acción no está permitida.
NOT_FOUND 404 Recurso o ruta no encontrada.
Ruta existente con otro método 404 actual El router no emite un 405 específico; si no hay match para el método recibido, cae como ruta no encontrada.
CONFLICT 409 Choque con el estado actual de la aplicación.
DEPENDENCY_UNAVAILABLE 502 o 503 Falla upstream o de transporte externo.
UNEXPECTED 500 Error no esperado; debe registrarse y presentarse seguro.

Surface toolkit y fachadas

Este catálogo ayuda a elegir el punto de acceso estable para una necesidad del navegador, como HTTP, feedback o un adapter visual. La integración consume esa fachada y conserva la responsabilidad de desmontar cualquier recurso que haya creado.

El catálogo con reglas de limpieza está en Toolkit, adapters y feedback.

Helper Uso Regla corta
toolkit/dom DOM, eventos, contenido y helpers de nodos. Debe usarse desde bindings o helpers UI.
workspace/integrations/<feature>/contracts.ts Tipos de request/response visibles para Surface. Lo importan api.ts y actions.ts; page.ts solo si necesita leer o anotar data.
workspace/integrations/<feature>/actions.ts Arma requests tipados desde valores semánticos y coordina feedback UI. Recibe valores de page.ts; no debe convertirse en service de dominio.
select2Adapter Selects enriquecidos. Destruir al desmontar.
dataTableAdapter Tablas con estado externo; la app consume la fachada de platform/infrastructure/adapters/datatable. No debe reemplazarse HTML sin destroy.
dateRangePickerAdapter Rangos de fecha. Limpiar el picker en unmount.
simpleModal Modales con HTML recibido; el remoto se resuelve desde la fachada de platform/infrastructure/feedback. Debe usarse withContentMount si trae fragments.
toastAdapter Toasts con HTML o fragment SSR desde la fachada de feedback. El contenido se desmonta al ocultarse.
swalAdapter Alertas, confirmaciones y formularios simples. No debe incluir negocio dentro del diálogo.

Outbound y connectors

Esta tabla separa lo que la aplicación necesita de la forma concreta en que un proveedor externo lo ofrece. Se consulta para ubicar la interfaz estable, su implementación y el punto donde se traducen respuestas o errores ajenos al sistema.

El flujo completo está en API HTTP clients externos.

Pieza Uso
EndpointRequest Request hacia endpoint externo con DTO único.
EndpointListRequest Request hacia endpoint externo que devuelve lista.
CustomPayloadRequestInterface Payload especial cuando propiedades públicas no bastan. El factory usa payload() si la request implementa esta interfaz; si no, usa get_object_vars(...). En contratos generados suele aparecer para serializar fechas: date-time como DateTimeInterface::ATOM y date como Y-m-d.
ContentType::MULTIPART Indica que el outbound debe usar opción multipart, no JSON.
HttpMethod::POSTFILE Método de compatibilidad que el cliente HTTP envía como POST.
ConnectorResult Resultado normalizado de integración para use cases.
ConnectorAliasRegistrar Alias por convención entre ports y connectors de Infrastructure/Outbound/Connector.
ServiceDefinitionFactory Lee services.json y variables API_* para definir base URI, bearer, timeout y TLS.
JsonServiceResponseMapper Valida si la respuesta externa es objeto o lista y falla si el shape no coincide.
ResponseHydrator Hidrata DTOs por constructor, tipos escalares, enums, fechas y objetos anidados. Fechas inválidas o enums no soportados pueden cortar la hidratación.

Señales de diagnóstico

Estas señales son pistas observables del runtime. Se parte del síntoma visible, se busca la señal correspondiente y se identifica la última frontera que produjo una salida válida. No expresan reglas de negocio ni sustituyen el error de aplicación; reducen el espacio de búsqueda antes de modificar código.

Señal Dónde mirar Qué confirma
X-CORRELATION-ID Response del navegador y logs Gateway. Une request, response y llamadas upstream.
LOG_TELEMETRY_ENABLED .env y configuración de observabilidad. Confirma si se emiten access, metrics, errores y spans normales por request.
ResponseLogContext Responses observables de Gateway. Resume éxito, mensaje, cantidad de errores y origen.
RouteCache Producción o build de Gateway. Indica si la tabla de rutas quedó desactualizada.
data-surface-<element>-status DOM renderizado en el navegador. Confirma si page o fragment cargó, montó o falló.
request_metrics Canal metrics de Gateway. Confirma duración, cantidad de upstreams, errores y llamada externa más lenta.
degraded_response / server_error_response / error_access Canal error o access de Gateway. Distingue respuesta degradada, error servidor emitido y request cerrada por error no manejado.
LogSanitizer Campos registrados en logs estructurados. Oculta secretos y trunca strings largos antes de persistir el evento.
Manifest Vite app-gateway/{PUBLIC_PATH}/ui-assets/.vite/manifest.json. Confirma qué entry, CSS e imports se sirven.
